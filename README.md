# Море чая — демонстрационный MVP

Адаптивный сайт сети чайных магазинов: каталог, корзина, оформление заказа, магазины на карте и админ-панель.

**Все товары, цены, остатки, контакты магазинов и тариф доставки в исходных данных — демонстрационные.** Они помечены в интерфейсе.

Репозиторий: https://github.com/mzakh0808-alt/charumag

## Локальный запуск

Рекомендуется Node.js 22 (версия указана в `.nvmrc`; проект также проверен на Node.js 24).

```bash
npm install
npm run dev
```

Откройте http://localhost:3000.

Дополнительные команды:

```bash
npm run typecheck  # TypeScript
npm run lint       # ESLint
npm run build      # production-сборка
npm start          # запуск production-сборки
```

Без `DATABASE_URL` локальная версия автоматически использует `data/db.local.json`. Исходные демоданные находятся в `data/demo.json`; локальный файл создаётся после первой записи и игнорируется Git.

## Возможности

- Поиск и фильтры каталога по категории, типу чая, стране, цене и наличию.
- Сортировка, пагинация и карточки товаров.
- Корзина в `localStorage`; цены и остатки повторно проверяются на сервере.
- Самовывоз из демо-магазина или доставка по демонстрационному тарифу.
- Создание заказа и списание остатков в транзакции PostgreSQL при работе на Vercel.
- Админка: создание и редактирование товаров, остатки по магазинам и складу, публикация и статусы заказов.
- Yandex Maps через публичный map-widget; API-ключ не нужен.
- Metadata, Open Graph, sitemap, robots, JSON-LD Product/Offer и LocalBusiness.
- Обязательное отдельное согласие на обработку персональных данных, сохранение времени и версии согласия.
- Mobile-first CSS, клавиатурный фокус и `prefers-reduced-motion`.

## Загрузка на Vercel

[Создать проект Vercel из этого репозитория](https://vercel.com/new/clone?repository-url=https://github.com/mzakh0808-alt/charumag)

`vercel.json` уже содержит настройки Next.js, установки и сборки. Отдельный Vercel CLI не нужен.

1. Импортируйте репозиторий `mzakh0808-alt/charumag` в Vercel.
2. Подключите управляемый PostgreSQL через Vercel Marketplace, например Neon, к вкладке **Storage** проекта.
3. Убедитесь, что интеграция добавила `DATABASE_URL` или `POSTGRES_URL` в Production и Preview.
4. Добавьте переменные окружения:

```text
ADMIN_EMAIL=ваш-email@example.com
ADMIN_PASSWORD=длинный-уникальный-пароль
SESSION_SECRET=длинная-случайная-строка-минимум-32-символа
NEXT_PUBLIC_SITE_URL=https://ваш-домен.ru
```

`NEXT_PUBLIC_SITE_URL` нужен для canonical URL, sitemap и микроразметки. Если переменная не задана, код попробует использовать `VERCEL_PROJECT_PRODUCTION_URL`.

5. Запустите **Deploy**. Таблица `more_chaya_state` и демонстрационные данные создаются автоматически при первом обращении к базе.

Без строки подключения PostgreSQL сайт на Vercel выдаст понятную ошибку конфигурации вместо записи во временную файловую систему. Это предотвращает молчаливую потерю заказов.

Для загрузки через CLI также можно выполнить:

```bash
npx vercel link
npx vercel env pull .env.local
npx vercel deploy --prod
```

Не добавляйте `.env.local` в Git.

```text

```

## Модель хранилища

Для MVP состояние каталога, остатков и заказов хранится в PostgreSQL в одной строке JSONB `more_chaya_state`. Изменения выполняются в транзакции с `SELECT … FOR UPDATE`, поэтому параллельные serverless-запросы не перезаписывают чужие изменения.

Это подходящий формат для демонстрации и небольшого MVP. При росте нагрузки и появлении сложных отчётов следует разнести модели из `lib/types.ts` по нормализованным таблицам и миграциям. Для локальной разработки без PostgreSQL используется атомарная запись JSON-файла с очередью изменений внутри одного процесса.

## Ограничения демо

- Нет онлайн-оплаты, личного кабинета, SMS/email и интеграции со службой доставки.
- Отмена заказа пока не возвращает остатки автоматически.
- Изображения товаров — стилизованные заглушки, загрузка файлов отсутствует.
- Юридический текст на `/privacy` требует замены и согласования.
- Перед реальным запуском нужны нормализованные миграции, роли администраторов, уведомления, ограничение частоты форм, мониторинг и резервное копирование.

## Допущения и вопросы к заказчику

1. Нужны реальные адреса, телефоны, геометки и часы работы каждого магазина.
2. Нужны ассортимент, составы, фасовки, цены, фотографии и правила управления остатками.
3. Следует уточнить зоны и тарифы доставки, способы оплаты и необходимость онлайн-оплаты.
4. Нужны реквизиты оператора персональных данных, утверждённая политика, сроки хранения и порядок отзыва согласия.
5. Для фактического соответствия 152-ФЗ требуется не только интерфейс согласия, но и организационные меры, включая размещение базы персональных данных в РФ. Регион Vercel и выбранной БД нужно проверить отдельно.
6. Следует предоставить фирменный логотип. Текущий зелёный знак с чашкой и волнами — временный векторный макет.
7. Перед production нужно решить, сколько администраторов будет у сайта и какие у них должны быть роли.
